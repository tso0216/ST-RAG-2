# 11: 門檻定案與可行性實驗

**What to build:** 用擴充後的 mock 做可行性驗證：

1. 只在 dev 題目上決定時空門檻和語意門檻的 δ。時空門檻要維持寬鬆，不能緊到等於硬過濾。
2. 在 test 題目上跑以下設定：
   - 完整系統
   - 兩個 baseline：dense、硬過濾
   - 消融：平滑頻寬設成 0、拿掉「不明」折扣、拿掉景點階層、oracle 模式、few-shot 規劃器、LLM 直接輸出分布
3. 對 ε、「不明」的折扣、平滑頻寬、時段梯形邊界做敏感度分析。
4. 輸出結果表，判斷是否達到可行標準：時間違規率明顯低於 dense retrieval，而且 recall 不低於硬過濾。
