# 11: 門檻定案與可行性實驗

**What to build:** 用擴充後的 mock 做可行性驗證：

1. 只在 dev 題目上決定語意門檻的 δ。
2. 在 test 題目上跑以下設定：
   - 完整系統
   - 兩個 baseline：dense、硬過濾
   - 消融：關掉時間退讓、關掉空間退讓、拿掉「不明」折扣、拿掉景點階層、oracle 模式、few-shot 規劃器
3. 對「不明」的折扣和 δ 做敏感度分析。
4. 輸出結果表，判斷是否達到可行標準：時間違規率明顯低於 dense retrieval；有回答率高於不退讓的硬過濾；時間誤植率夠低。

**Blocked by:** 03, 06, 07, 09, 10, 12

**Status:** ready-for-agent

- [ ] 門檻只用 dev 題目決定，決定過程和最後的數值有紀錄
- [ ] test 結果表涵蓋所有設定，指標包含：集合 recall、precision、F1，時間違規率，有回答率，規劃器正確率，`expect` 覆蓋率，時間誤植率，並依題型分組
- [ ] 敏感度分析的結果有紀錄
- [ ] 寫一段結論：是否達到可行標準、哪類題目比較弱、下一步的建議
