# 03: 景點階層與退讓

**What to build:** 讓系統認得同一個景點的不同名稱，以及景點之間的包含關係。

階層檔：

- 定一份放在 repo 資料區、受版本控制的階層檔格式。每個節點記錄正式名稱、別名和母節點；節點可以是景點，也可以是區域，例如「淺草」「押上」。
- 起草現有 `place` 表的階層，交給研究者審稿。第一版只做別名合併和一層母子關係，不用座標。

系統行為：

- 計畫裡的地點名稱先比對別名，比對不到再用名稱 embedding 找最近的節點。
- 問母景點時，一律把子景點的片段納進來。
- 一筆都沒過門檻時，`space` 往上退一層，改查母節點。
- 還是沒有，就回傳空結果，並附上最接近的時段資訊。時間門檻不放寬。
- 生成時揭露退讓，沒有證據時明說沒有。
