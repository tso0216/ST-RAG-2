# 12: 時段硬過濾、時間退讓、重新抽取

**What to build:** 把時間比對從「分布加平滑」改成「時段硬過濾加時間退讓」（見 `docs/adr/0001-hard-time-filter-with-backoff.md` 和 spec 的「時段的鐘點邊界」「模組 1、4」）。取代 02 的平滑、重疊度和揭露做法。

抽取：

- 抽取 prompt 的 `time` 只能填早上、中午、下午、晚上、全天、不明，照 spec 的鐘點邊界表判斷；`content` 要保留原文提到的具體時間。`month`、`day_type` 格式不變。
- 重新抽取 `main.db`（會呼叫抽取用的 LLM，跑之前先跟研究者確認）。片段 id 會變，mock 題目檔的 `relevant_contents` 要重新對應，交給研究者確認。

檢索：

- 月份、平日／假日、時段三個維度都硬過濾，留空不限。片段是 `全天` 時問任何時段都相符；片段某個維度是 `不明` 時算相符，但標成時間不明，分數乘上 `unknown_discount`。
- 分數只剩語意分數（乘上 `不明` 折扣），門檻保留「最高分 − δ」。刪掉 ε、`overlap_min`、時間分布、平滑、時段梯形、「時間相符程度」。
- 退讓順序：時間退讓（時段和月份各往外擴一格，都是環狀的；平日／假日不擴）→ 空間退讓（母節點，時間用原本的條件）→ 空結果，附上這個景點（含子孫節點）有資料的時段和月份，以及各有幾筆。取代 `nearest.py` 的距離加權。
- 時間退讓、空間退讓各自可以關掉。
- 每筆證據帶三個標記：時間退讓、空間退讓、時間不明。
- `group_by` 的 `time_of_day` 直接照片段的時段分組，`全天`、`不明` 各成一組；`month` 照片段的月份標籤分組。

規劃和生成：

- 規劃器 prompt 的 `time` 改成一個或一組時段，附上鐘點邊界表；`month` 可以是一組月份、範圍或季節。
- 生成器照三個標記揭露；沒有證據時列出這個景點有資料的時段和月份。

題目檔：

- mock 三個題目檔的 `when` 和 `gold_plan` 改成新格式（例如 `16-17` → `下午`）。
