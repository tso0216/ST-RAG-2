# 02: 週期平滑、「不明」折扣、揭露

**What to build:** 讓時間比對真正變成「週期性」的軟比對：

- 月份軸和小時軸套上頭尾相接的平滑核：十二月和一月相鄰，23 點和 0 點相鄰。
- 平日／假日這一維不平滑。
- 片段只要有任何一個時間維度是 `不明`，分數就再乘上一個小於 1 的折扣。
- 生成器看到時空重疊度低的證據時，要講明它跟問題差在哪，例如「這是一月的經驗，你問的是十二月」。

**Blocked by:** 01

**Status:** ready-for-agent

- [x] 平滑頻寬和「不明」的折扣都是可調參數；頻寬設成 0 時，結果跟沒有平滑時完全一樣
- [x] 檢索 seam 測試涵蓋以下行為：
  - 問十二月時，一月的片段會取回，但排在十二月的片段之後；頻寬設成 0 時，一月的片段取不回來
  - 問 23 點時，0 點的片段也會取回
  - 時間 `不明` 的片段，排在時間明確而且相符的片段之後
- [x] 時空門檻寬鬆到相鄰時段在平滑後能通過，例如問十二月時一月能通過
- [x] 生成的答案會揭露重疊度低的證據跟問題的時間落差

## Comments

實作摘要與需要研究者決定的事項：

- **預設值**（`params.py`，依常理定，未在 test 題目上調）：
  - `month_bandwidth = 0.5`、`hour_bandwidth = 1.0`：頭尾相接的高斯核標準差，單位是月、小時。月和小時單位不同，所以分成兩個參數；消融時兩個都設 0。
  - `unknown_discount = 0.8`。
  - `overlap_min` 維持 0.05，不用調：問十二月時一月的重疊度約 0.21、二月約 0.015（擋掉）；問 23 點時 0 點約 0.55；問 16–18 點時 14 點約 0.16、13 點約 0.04（擋掉）。
- **平滑套在問題和片段兩邊**（照 spec「片段和問題的時間標籤都轉成分布……會平滑」）。副作用請確認是否接受：
  - 完全相符的片段，重疊度不再是 1：月份相符約 0.82，小時相符約 0.71，月份和小時都相符約 0.58。排序不受影響，但重疊度的絕對值跟 01 不同，之後在 dev 上定門檻時要用平滑後的數字。
  - 範圍型問題的邊緣會略低於中間：問「冬」時，十二月、二月的片段約 0.82，一月約 0.98。
  - 如果希望「完全相符 = 1」，替代做法是只平滑片段那一邊，或把問題的隸屬度改成取 max 的擴張；這會偏離 spec 的字面，需要研究者決定。
- 01 的 `test_better_time_match_ranks_first_and_evidence_carries_scores` 斷言的是未平滑的重疊度（1 和 1/3），改成固定用頻寬 0，順便驗證「頻寬 0 = 不平滑」。
- 「不明」折扣照 spec 字面，不管問題有沒有限制那個維度都會套用；只影響排序，不影響語意門檻。
- 生成器 prompt 除了時間落差，也加了一條「標成 `不明` 的部分要說明時間不確定」，略超出 ticket，覺得不需要可以刪。
- **實跑確認**（main.db 副本）：問「十二月平日早上去東京晴空塔，看得到富士山嗎？要排多久？」，DB 裡晴空塔只有 1、5、8 月的片段。取回 3 筆一月平日早上的片段（重疊度 0.11–0.18，頻寬 0 時取不回來）。答案開頭寫「資料裡沒有十二月的經驗，下面都是同一位旅客某個一月平日早上去晴空塔的經驗，跟你問的十二月差了一個月」，結尾也提醒不保證十二月一樣。
