# 04: 多子查詢與分組

**What to build:** 檢索計畫支援一到多個子查詢，並支援 `group_by` 和 `compose` 兩個設定：

- `group_by` 可以從 `month`、`day_type`、`time_of_day`、`place` 中選一個或多個；每個片段分到它分布質量最大的那一組。
- `compose` 是 `merge` 或 `contrast`。

這樣「什麼時候去人比較少」可以依時段整理；「傍晚哪裡適合看夕陽」可以依地點整理；「十二月傍晚跟晚上哪個比較不擠」可以分兩個子查詢各自找證據，再對照作答。

規劃器維持 zero-shot，prompt 只說明格式，不放範例，也不提題型名稱，讓 LLM 自己組出計畫。

**Blocked by:** 01

**Status:** resolved

- [x] 規劃器的輸出格式支援多個子查詢、`group_by`、`compose`，格式說明寫進規劃器的 prompt
- [x] 檢索 seam 測試涵蓋以下行為：
  - `group_by` 照指定的維度分組
  - 多個維度可以同時分組
  - `compose=contrast` 時，各子查詢的結果分開交給生成器
- [x] 生成器依分組和對照結構作答
- [x] 用現有 eval 的比較題（例如澀谷 SKY 十二月傍晚和晚上的比較），規劃器能產生兩個子查詢的計畫，答案有對照兩邊

## Comments

實作摘要（issue 04）：

- `Plan` 新增 `group_by`（`month`、`day_type`、`time_of_day`、`place`，可多選、照列出的順序）和 `compose`（`merge`／`contrast`，預設 `merge`）。
- 新模組 `rag/group.py`：`Retriever.retrieve_grouped(plan, question)` 回傳交給生成器的段落（`Section`），每段再依 `group_by` 分組（`Group`）。`merge` 把所有子查詢的證據合成一段（同一片段只留分數最高的那筆）；`contrast` 每個子查詢一段。原本的 `Retriever.retrieve` 不變。
- 生成器的輸入改成依段落和分組組織；`python -m strag_v3.rag --json` 多了 `sections`，`results` 照舊。

需要研究者決定的地方：

- **分組的並列與邊界規則**是我先訂的：時間維度的邊際分布是均勻的（`不明`）時另成「不明」組；兩組質量並列時歸給順序在前的組（月份 1→12、平日→假日、早上→中午→下午→晚上→深夜）。分組用的是平滑後的分布（issue 02），所以在預設頻寬下 `冬` 歸 1 月、`16-17` 歸晚上（12 點那側的尾巴算進中午）、`全天` 也歸晚上；頻寬設成 0 時 `16-17` 會並列，歸下午，`全天` 歸早上。`全天` 被歸到單一時段可能會誤導，要不要另成一組請研究者決定。
- **`time_of_day` 的分組表**（`group.TIME_OF_DAY_GROUPS`）：早上 5–10、中午 11–12、下午 13–16、晚上 17–23、深夜 0–4。依 `DEFAULT_PERIODS` 梯形值最高的時段切，交界歸後面的時段；「深夜」是五個時段詞以外新加的組名。這張表跟 `planner.md` 的說明是兩處各寫一次，改的時候要一起改。
- **組的順序**：時間維度照上面的固定順序；`place` 照該地點最高分的證據排。
- **q3 實測**（`十二月去澀谷 SKY，傍晚跟晚上哪個時段比較不擠？`）：規劃器產生兩個子查詢（12 月 `16-18`、12 月 `晚上`，aspect 都是「人潮擁擠程度」），`compose=contrast`、`group_by=[]`。傍晚段取回 25、24、26、22，晚上段取回 23、26、22、25、24，剛好涵蓋 `relevant_contents` 的 22–26。答案先分開說明兩個時段，再拿來對照，也講明是兩位旅客不同天的經驗；`expect` 三點都有提到：週末傍晚日落前後的票售完、要預約、熱門位置排約四十分鐘、看得到富士山，平日晚上現場買票、人很少、下雨時頂樓暫停。合入 issue 02 之前，片段 24（`15` 點）因為傍晚被換成 `16-18` 而取不回來，「要預約」就沒出現；平滑合入後才取得回來。答案的結論比 `expect` 保守，因為它指出晚上人少的那次剛好是平日又下雨，不一定是時段本身的關係。
- **Code review 修正後（`feat/rag-02-04` 3523476）**：
  - `month`、`time_of_day` 分組改用片段自己標籤的不平滑分布，不隨平滑頻寬改變，所以 `16-17` 歸下午。`全天` 自成一組。
  - `planner.md` 不再列時段表，表只在 `group.TIME_OF_DAY_GROUPS`，上面「兩處各寫一次」的說法已經不適用。
  - `Retriever.retrieve` 是唯一的檢索 seam，輸出分好組的 sections。`--json` 最上層的 `results` 拿掉了，改成每個 section 各自帶 `results` 和 `groups`。
