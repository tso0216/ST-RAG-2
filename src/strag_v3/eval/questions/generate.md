# 出題提示詞：ptt_v2 評測題

你要用 `data/ptt.db` 的旅遊片段，替 strag_v3 出 5 種題型、每型 10 題的評測題，連同標準答案：收哪些片段（`relevant_contents`）、答案要講到哪些重點（`expect`）。題目檔寫在 `src/strag_v3/eval/questions/ptt_v2/`。

## 為什麼要這麼嚴

回答題目的是 LLM，打分的也是 LLM。評審（`src/strag_v3/eval/full/judge.md`）逐條看 `expect`：意思到了算涵蓋，只講到一部分或講反了不算，而且只看答案、不回頭看證據。`relevant_contents` 拿來算檢索的 recall 和 precision。所以標準答案的每個瑕疵都會直接變成錯分：

- 收錯片段：系統撈到真正相關的片段，被算成誤撈；標準答案收了不相關的，系統沒撈到被算成漏撈。
- `expect` 寫了片段沒說的事（推論、建議、自己算的數字、把一個設施講成全部）：系統照證據老實回答，反而拿不到分。
- `expect` 一條塞好幾件事，或程度說得含糊：答案只講到一半就整條不算，評審每次判得不一樣，分數變成雜訊。

舊題庫（`questions/ptt/`）就是這樣出問題的：「熱門設施不用等」其實片段只講了一個設施；「3.5 到 6 倍」是標註者自己算的；「要說明是不同旅客」是對回答方式的要求，不是事實；「人多嗎？晚上還有什麼可看？」一題問兩件事。

原則：每個判斷都要能指回片段裡的一句原文。指不回去，或兩個認真的人會判得不一樣，就換題，不要硬標。湊不滿 10 題就少出，在報告裡說明，不要放寬任何一條規則。

## 系統怎麼找片段

標準答案要跟系統用同一套規則，候選片段才對得起來。這些規則已經寫進 `scripts/eval/qgen.py`，不必自己實作，但要懂才出得對題目。

- **片段**：一篇 PTT 遊記拆成多個片段，每個片段標了地點（`poi`）、月份（`1`–`12`、`春` `夏` `秋` `冬`、`M-M`、`不明`）、平日／假日（`平日`、`假日`、`不明`）、時段（`早上`、`中午`、`下午`、`晚上`、`全天`、`不明`）。同一篇文章（`article`）是同一位旅客。
- **地點範圍**：問景點，只撈標在這個景點的片段；問區域（行政區，例如淺草、押上、台東區），撈區域本身和範圍內所有地點的片段。planner 會把景點的局部（展望台、境內建築、參道）歸到所在的景點。
- **時間條件**：月份取交集（春 3–5、夏 6–8、秋 9–11、冬 12–2 月），平日／假日要相同，時段要相同。片段標 `全天` 符合任何時段；標 `不明` 也算符合，但會標成「時間不明」交給回答者。
- **退讓**：原條件撈不到通過相關性門檻的片段，就依序改試：時間退讓（月份和時段各往外擴一格，平日／假日不擴）→ 空間退讓（改撈外圍行政區，用原本的時間）→ 都沒有就回答「沒有符合的經驗」。
- **planner 的時間換算**：早上 5–10 點、中午 11–13 點、下午 14–17 點、晚上 18–4 點（含深夜、凌晨）；傍晚算 `下午`＋`晚上`，10–12 點算 `早上`＋`中午`；週末和國定假日都算 `假日`。

## 工具

從專案根目錄跑 `.venv/bin/python scripts/eval/qgen.py <指令>`。DB 以唯讀開啟。

| 指令 | 用途 |
|---|---|
| `places [--min 3]` | 有片段的地點：id、種類、中文名、日文名、城市、片段數 |
| `areas` | 有範圍的行政區，和範圍內的片段數（找地點題用） |
| `pool <地點 id> [--when '<json>'] [--widen]` | 候選片段，跟檢索同一套規則，印出全文。`--widen` 是時間退讓後的候選。每筆會標出「限定維度不明」 |
| `outer <地點 id>` | 空間退讓會去的外圍行政區 |
| `layers <地點 id> [--when '<json>']` | 檢索依序試的每一層：層名、撈的地點、時間條件（時間退讓層印擴大後的）、候選數、其中限定維度不明的筆數。不印片段內容 |
| `frag <片段 id>...` | 印指定的片段，格式跟 `pool` 一樣 |
| `usage [資料夾]` | 資料夾（預設 `ptt_v2/`）裡的題目檔用掉的地點：各題型和合計的題數，標出到上限的；再列出已出過的（地點、面向、時間條件）組合 |
| `merge <題目檔> <草稿>...` | 草稿裡的題目依 id 排序，合併成題目檔。id 重複就報錯，不寫檔 |
| `blind-input <題目檔> [題目 id...]` | 給盲審子代理的 JSON：開頭說明要判什麼、結果寫成什麼格式；每題只帶題目要素和要判的層（撈的地點範圍、時間條件、`pool` 指令、要判的片段 id），不帶標註 |
| `blind-diff <題目檔> <盲審檔>...` | 標註 × 盲審的三類對照表和一致率，逐筆列出不一致的；再列出盲審漏判的候選、判了候選以外的片段、盲審引文不是片段原文的 |
| `check <題目檔>...` | 機械檢查，見〈驗證〉 |
| `plan <題目檔>...` | 讓 planner 只讀題目文字，比對它還原出的地點和時間（每題 1 次 Opus 呼叫） |
| `answer <題目檔> <id>` | 只用 `expect_sources` 原文拼成的正向答案 |
| `calibrate <題目檔> --negatives <json>` | 用真正的評審校準 `expect`（每題 2 次 Opus 呼叫） |

## 流程

一次做一個題型，順序：停留經驗 → 移動經驗 → 找地點 → 找時間 → 比較。一個題型的 `check`、`plan`、盲審、校準全部通過，才做下一個。

每一題：

1. **找題材**：用 `places`、`areas`、`pool <id>`（先不加時間）讀片段，找出某個面向在某個時間有 1–8 筆明確描述的組合。
2. **先定題目要素，再判候選**：`space`、`when`、`aspect`、`aspect_rule`（找時間題加 `asks`，比較題加 `options`）。`aspect_rule` 寫好才開始判片段；判到一半想改，就改完整題重判。
3. **逐筆判候選**：`pool` 撈出的每一筆，不是收進 `relevant_contents`，就是寫進 `excluded` 附理由碼。
4. **定 `coverage`**。
5. **寫題目文字**。
6. **寫 `expect` 和 `expect_sources`**。

一個題型寫完後依序跑 `check` → `plan` → 盲審 → 校準。任何一步改了題目，從 `check` 重跑。五個題型都做完後，再對五個檔一起跑一次 `check`（有跨題型的上限）。

## 規則

### 1. 題型

每題都要有空間和時間，各自可以是條件或答案。由上往下判斷，第一個符合的就是題型：

| 順序 | 判定 | 題型 | 空間 | 時間 |
|---|---|---|---|---|
| 1 | 列出兩、三個選項要比較 | 比較 | 條件或選項 | 條件或選項 |
| 2 | 要的答案是時間（哪個時段、哪個月、平日或假日） | 找時間 | 條件 | 答案 |
| 3 | 要的答案是地點（去哪、哪裡） | 找地點 | 答案（區域內的地點） | 條件 |
| 4 | 問移動，或搭交通工具本身 | 移動經驗 | 條件 | 條件 |
| 5 | 其餘：某地點在某時間的狀況 | 停留經驗 | 條件 | 條件 |

- **比較**：選項之間只差一個維度（同一時間的兩個地點，或同一地點的兩個時間）。題目層的 `when` 只放選項共同的條件；每個選項寫完整的 `space` 和 `when`。
- **找時間**：`asks` 填問的維度（`time`、`month`、`day_type`）；`when` 只放其他限定，沒有就是 `null`。
- **找地點**：`space` 是 `areas` 裡有的行政區；收的片段至少涵蓋 2 個地點。條件下的候選超過 50 筆，就換小一點的區域或加時間條件。
- **移動經驗**：`space` 是移動經驗發生的那個地點（車站、機場、場館出口）。

### 2. 選地點

- `places` 印出的中文名、日文名要跟片段的 `poi` 指同一個地方。下列地點的片段標錯了地點，不要用：目黑川、東京大學、池袋 Animate、合羽橋、江之島、隅田川 Terrace、隅田川河岸、淺草橫町、函館山、東武淺草站。新發現的記進報告。
- 不要拿另一個景點的局部當 `space`（雷門、仲見世通是淺草寺的一部分，晴空塔展望台是晴空塔的一部分）：planner 會把局部歸到所在景點，題目問雷門，系統卻去撈淺草寺。要問局部，就問所在的景點，或問包含它們的區域。
- 同一個地點：同一題型最多 2 題，五個題型合計最多 6 題。不要出地點、面向、時間條件都一樣的兩題。

### 3. 時間條件（`when`）

- 格式跟 planner 一樣：`{"month": ["3"], "day_type": "平日", "time": ["早上"]}`，沒限定的維度省略。
- 題目文字的時間說法，要能照〈系統怎麼找片段〉的換算規則換成唯一一個 `when`。不要用換算不出來的說法（櫻花季、紅葉季、連假、跨年、聖誕節），除非同時講了月份。
- 停留經驗、移動經驗、找地點一定要有時間條件。

### 4. 面向（`aspect`）與判準（`aspect_rule`）

每題只問一個面向，從下表選；寫面向本身，不寫方向（寫「人潮多寡」，不寫「人少」）：

| 面向 | 例 |
|---|---|
| 人潮多寡 | 人多不多、擠不擠、拍照有沒有路人 |
| 排隊／等待時間 | 設施、入場、餐廳、入境要排多久 |
| 開放狀況 | 有沒有開、幾點關門、有沒有點燈 |
| 景觀能見度 | 看不看得到富士山、夜景清不清楚 |
| 花況 | 櫻花、紅葉開到幾分、落了沒 |
| 交通狀況（移動經驗用） | 要多久、班次、等車、車上擠不擠 |

不出：值不值得、推薦、好不好玩、有什麼可看可吃可玩、要注意什麼、怎麼安排。

`aspect_rule` 是這題的判準，格式「算：…；不算：…」，判片段之前寫好。「算」列出哪些說法算描述這個面向，「不算」列出容易混淆但不收的說法。例如人潮多寡：

> 算：明說人的多寡或擁擠（人多、人少、擠、空蕩蕩、沒什麼人、排隊人龍、拍照不用閃路人）；不算：只講氣氛（寧靜、靜謐、熱鬧、喧鬧、莊嚴），或要再推一步才知道人多人少的（店家都關了）

題目問「哪裡人比較少」「什麼時段人比較少」時，說人多的句子照樣算：面向是人潮多寡，不是人少。

### 5. 收不收片段

候選同時滿足下面四條，才收進 `relevant_contents`：

1. 片段裡有一句照 `aspect_rule` 算數的句子。
2. 那句講的是範圍內的地點：景點題是這個景點或它的一部分（境內建築、參道），區域題是區域裡的地點。
3. 那句自己寫的時間（「白天來的時候」「9 點以後」）不跟條件衝突。
4. 題目限定的維度（找時間題再加上問的維度），片段的標籤都確定：不是 `不明`，月份標籤也不比條件粗（問 3 月，片段標 `春`，說不準是不是 3 月）。唯一例外：那句話本身寫了符合條件的時間，這時照收，並在 `label_issues` 記一筆。

以句子為單位判斷：一個片段只要有一句通過四條就收；`expect` 只用通過的句子。

不收的寫進 `excluded`，理由碼取下表第一個符合的：

| 理由碼 | 意思 |
|---|---|
| `無關` | 沒有一句照 `aspect_rule` 算數 |
| `別處` | 有算數的句子，但講的是範圍外的地點 |
| `時間矛盾` | 算數的句子自己寫的時間跟條件衝突；同時記進 `label_issues` |
| `時間不明` | 內容和地點都對，只是限定的維度說不準（第 4 條） |

`時間不明` 的片段，系統會撈到並標成時間不明交給回答者；但我們不知道它是不是那個時間，所以不當標準答案，評分時也不計分：撈到不算誤撈，沒撈到也不算漏撈。因此這個理由碼要判準：內容不相關的一律寫 `無關`，寫成 `時間不明` 的話，系統誤撈它也不會被扣分。

數量：每題收 1–8 筆（比較題每個選項至少 1 筆）；同一題型裡只收 1 筆的題目最多 3 題。超過 8 筆就縮小時間條件或換地點。

### 6. `coverage`

照檢索的順序一層一層看，停在第一個有收進片段的層：

| `coverage` | 意思 |
|---|---|
| `exact` | 原條件就有 |
| `time_backoff` | 原條件沒有，時間退讓後的候選（`pool --widen`）有 |
| `space_backoff` | 前兩層都沒有，外圍行政區（`outer`，用原本的時間）有 |
| `none` | 都沒有 |

- 前面任何一層有 `時間不明` 的片段就換題：不明算相符，系統會停在那層，跟標準答案對不起來。
- 退讓和 `none` 只出在停留經驗、移動經驗、找地點，每個題型最多 2 題，其餘都是 `exact`。找時間、比較只出 `exact`。
- 從第一層到停下的那層，每個候選都要判過（`none` 是每一層）。

### 7. 題目文字

- 只表達 `space`、`when`、`aspect` 三件事，一題只問一件事。
- 用旅客會問的口語。不要抄片段裡有特色的詞或答案的關鍵字（不要問「仲見世通是不是空蕩蕩的？」）。
- 題目裡只出現一個地名（比較題每個選項一個）。移動經驗的另一端用泛稱：市區、車站、飯店。多一個地名，planner 可能多開一個子查詢。
- 區域題要看得出問的是區域：「台東區」「淺草一帶」。

### 8. `expect`

`expect` 是評審逐條比對的重點。`expect_sources` 跟它一條對一條，格式 `{片段 id: 原文子字串}`。

**一條一個狀態值**：面向的值（人很多、幾乎沒什麼人、排 60 分鐘、沒開），加上句子裡跟它綁在一起的限定：鐘點、數量、子區域、比較對象。這些限定拿掉，說法會變得比原文廣，所以要留。句子以外的東西不要加：題目沒問的時間標籤、旅客身分、天氣。

**開頭**：

- 停留經驗、移動經驗：直接寫狀態，不重複題目給的地點和時間。
- 找時間：先寫片段在問的維度上的標籤值，例如「早上：8 點開門時幾乎沒什麼人」。時段標 `全天` 的寫「整天：」。
- 找地點：先寫地點名，例如「十間橋：…」。
- 比較：先寫選項名稱，例如「平日早上：…」。
- `time_backoff`：先寫片段在題目限定維度上的實際標籤，例如「4 月早上：…」（題目沒限定的維度不寫）。不寫揭露條：開頭的時間已經要求答案講明這是哪個時間的經驗，評審也會另外抓時間誤植。
- `space_backoff`：第一條是揭露條「說明資料裡沒有<地點>本身<時間條件><面向>的經驗」，對應的 `expect_sources` 是 `{}`；之後每條先寫實際的地點名。
- `none`：只有一條揭露條「說明資料裡沒有<地點><時間條件><面向>的經驗」，`expect_sources` 是 `[{}]`。

**合併**：不同片段講同一個值、同樣的限定，寫成一條、引用多個 id；值或限定不一樣（不同鐘點、不同子區域）就分開寫。合併後的整條，每個來源都要撐得住。

**照原文的程度和範圍**：「幾乎沒什麼人」不能寫成「沒人」；只講一個設施，不能寫成「設施都…」；只有一位旅客，不能寫成「通常」。數字照抄，用阿拉伯數字，不換算、不相加、不算倍數或區間。

**不寫**：

- 推論、建議、結論、總結（「所以假日要更早到」「整體來說平日比較好」）
- 跨片段的概括（「通常」「大多」「一般」）
- 片段自己沒做的比較（兩位旅客各自的經驗，不能寫成「假日比平日多」）
- 對答案的要求（「要說明是不同旅客」「不能用常識補」）
- 否定型的重點（「兩位旅客都沒寫排多久」）

旅客自己說的比較或建議可以寫，寫成「有旅客說…」，關鍵詞照原句。

**完整**：每個收進來的片段至少被一條引用；收進來的片段裡，每一句通過〈收不收片段〉四條的算數句子都要落在某一條裡。每題 1–8 條（揭露條不算）；寫不下就縮小條件或換題。

`expect_sources` 的原文要從片段逐字複製：可以截短，不能改字，也不能把兩段拼成一段。

### 9. 驗證

**`check`**：每次改完都跑，要全部通過。它會檢查：候選都判過、收的片段在對的那層、理由碼跟標籤一致、`coverage` 停在對的層、`relevant_articles` 由 `relevant_contents` 推得、引文是原文子字串、`expect` 裡的數字都出現在引文或月份標籤裡、沒有引文裡沒有的推論用語（通常、大多、建議、倍……）、沒有中文數字、每個收進來的片段都被引用，以及數量和分布上限。

**`plan`**：讓 planner 只讀題目文字，看它還原出的地點和時間跟標註是否一樣。不一樣時先問：題目文字有沒有兩種讀法？有就改題目文字（最多改兩次）；文字只有一種讀法、是 planner 讀錯，就保留題目，記進報告。「快取解析不到」代表 planner 寫的日文名不在地點快取裡，換一個更常見的地名寫法。

**盲審**：用 `blind-input` 產生盲審的輸入存成檔，再用 Agent 工具開一個新的子代理，只給它這個檔和本提示詞的〈收不收片段〉。這個檔只帶每題的 `question`、`type`、`when`、`asks`、`aspect`、`aspect_rule`，以及 `pool` 印出的候選（退讓題給每一層，片段全文讓子代理跑檔裡每層的 `pool` 指令看）；不帶你的判斷。請它照檔頭的說明逐筆判收或不收，收的附算數那句原文，不收的附理由碼，寫成盲審檔。用 `blind-diff` 對照兩邊：

- 規則判得出誰對，就改錯的那邊（也可能是你）。
- 規則判不出來，代表 `aspect_rule` 沒寫清楚：補清楚後整題重判，再請子代理重審這題；還是不一致就換題。
- 理由碼是不是 `時間不明` 也要一致，因為它決定這個片段計不計分。
- 記下每個題型修正前的一致率，分成三類對照：收、不計分（`時間不明`）、其他不收（就是 `blind-diff` 印的對照表）。

再開另一個子代理審 `expect`：給它 `question`、`aspect_rule`、收進來的片段全文、本提示詞的〈`expect`〉，以及 `expect` 和 `expect_sources`。收進來的片段全文用 `frag` 取。請它逐條回答：每個部分都有引文撐住嗎？程度和範圍跟原文一樣嗎？是不是只有一個狀態值？收進來的片段裡，有沒有算數的句子沒被任何一條涵蓋？有問題就修。

**校準**：用真正的評審測 `expect`。

1. `answer` 印出每題的正向答案（只用引文拼成）。
2. 每題寫一個反向答案，存成 `ptt_v2/calibration/<題型檔名>.json`，格式 `{題目 id: 反向答案}`。照正向答案的寫法，但把每一條的關鍵值改錯（人多改人少、60 分鐘改 15 分鐘、換子區域或鐘點）。`time_backoff` 題把實際時間改成題目問的時間；`space_backoff` 題拿掉揭露條，把別處的經驗說成問的地點；`none` 題編一段經驗。
3. `calibrate` 要印出「正向全部涵蓋、反向全部擋住」：
   - 正向沒涵蓋：那條寫得不清楚，或塞了引文沒有的東西。改那條，不是改答案。
   - 反向沒擋住：先確認反向答案真的改了那條的關鍵值；有改，就是那條太模糊，把關鍵值寫明。
   - 改三輪還不過就換題。

## 檔案

`src/strag_v3/eval/questions/ptt_v2/` 下五個檔：`stay.json`、`move.json`、`find_place.json`、`find_time.json`、`compare.json`。id 依序是 `stay-01`…、`move-01`…、`place-01`…、`time-01`…、`cmp-01`…。檔案格式：

```json
{"annotation_note": "依 src/strag_v3/eval/questions/generate.md 出題與標註", "questions": [...]}
```

不要寫 `split`。每題的欄位：

| 欄位 | 說明 |
|---|---|
| `id`、`type`、`question` | |
| `when` | 時間條件；比較題只放選項共同的條件 |
| `space` | `{"place_id", "name", "kind"}`；比較題改寫在 `options` 裡 |
| `options` | 只有比較題：`[{"label", "space", "when", "relevant_contents"}]` |
| `asks` | 只有找時間題：`time`、`month`、`day_type` |
| `aspect`、`aspect_rule` | |
| `coverage` | `exact`、`time_backoff`、`space_backoff`、`none` |
| `relevant_contents` | 收的片段 id |
| `relevant_articles` | 收的片段所屬的文章 |
| `excluded` | `{片段 id: 理由碼}`，每個沒收的候選都要有 |
| `expect`、`expect_sources` | |
| `label_issues` | `[{"id", "note"}]`：標籤跟內文對不上的片段 |

### 範例

範例只示範格式和判斷方式。要收進題庫，就當成新題目從頭走一遍流程。

**停留經驗、`exact`（完整的一題）**：

```json
{
  "id": "stay-01",
  "type": "停留經驗",
  "question": "三月晚上去淺草寺，人多嗎？",
  "when": {"month": ["3"], "time": ["晚上"]},
  "space": {"place_id": 50, "name": "淺草寺", "kind": "景點"},
  "aspect": "人潮多寡",
  "aspect_rule": "算：明說人的多寡或擁擠（人多、人少、擠、空蕩蕩、沒什麼人、排隊人龍、拍照不用閃路人）；不算：只講氣氛（寧靜、靜謐、熱鬧、喧鬧、莊嚴），或要再推一步才知道人多人少的（店家都關了）",
  "coverage": "exact",
  "relevant_contents": [6, 611],
  "relevant_articles": ["ptt_M.1498415528.A.484", "ptt_M.1753067813.A.29B"],
  "excluded": {
    "12": "無關", "73": "無關", "115": "無關", "119": "無關", "121": "無關", "151": "無關",
    "4": "時間不明", "22": "時間不明", "106": "時間不明", "117": "時間不明", "118": "時間不明", "140": "時間不明",
    "141": "時間不明", "142": "時間不明", "152": "時間不明", "156": "時間不明", "179": "時間不明", "305": "時間不明"
  },
  "expect": ["觀光客少很多", "仲見世通空蕩蕩"],
  "expect_sources": [
    {"6": "晚上白天的觀光人潮已散去", "611": "觀光客少了很多"},
    {"6": "仲見世通り空蕩蕩"}
  ],
  "label_issues": []
}
```

判斷說明：

- 6 的「風雷神門一帶很寧靜」、73 的「感覺很靜謐」、151 的「少了喧鬧、更顯莊嚴」都是氣氛，照 `aspect_rule` 不算。73、151 沒有別的算數句子，所以是 `無關`。
- 4、22、141 等都描述了人潮，但限定的月份或時段說不準（140 標 `春`，不一定是 3 月），所以是 `時間不明`。
- 611 沒標平日或假日，但題目沒限定這個維度，照收。
- 6 和 611 講的是同一個值，合成一條；「仲見世通空蕩蕩」帶著子區域，自成一條。

**停留經驗、`time_backoff`（只列關鍵欄位）**：題目「三月晚上去隅田公園，人多嗎？」，`when` 跟上一題相同，`space` 是隅田公園（60）。原條件沒有候選；時間退讓（2–4 月；早上、下午、晚上）後收 87、137。20 的「公園裡觀光客很少」標 `春`，排除為 `時間不明`。87 說「往南的觀光船乘船處和橋上…人潮很多」，137 說「排隊搭船的人也不少」，講的都是公園外的搭船處，這兩句不寫進 `expect`。

```json
"coverage": "time_backoff",
"relevant_contents": [87, 137],
"expect": ["4 月早上：公園裡人很少，觀光客只有約 5 人以內", "3 月下午：賞花的人很多"],
"expect_sources": [
  {"87": "公園裡人很少,多是附近居民散步、運動或遛狗,觀光客含作者只有約 5 人以內"},
  {"137": "賞花的人很多"}
]
```

**比較（只列關鍵欄位）**：

```json
"question": "淺草寺平日早上跟假日早上，人潮差在哪？",
"when": {"time": ["早上"]},
"options": [
  {"label": "平日早上", "space": {"place_id": 50, "name": "淺草寺", "kind": "景點"},
   "when": {"day_type": "平日", "time": ["早上"]}, "relevant_contents": [67, 124]},
  {"label": "假日早上", "space": {"place_id": 50, "name": "淺草寺", "kind": "景點"},
   "when": {"day_type": "假日", "time": ["早上"]}, "relevant_contents": [62, 135]}
],
"expect": [
  "平日早上：8 點開門時幾乎沒什麼人",
  "平日早上：8 點多雷門只有零星幾人拍照",
  "平日早上：8 點過後人開始變多",
  "假日早上：大批觀光客湧入前拍照，畫面很乾淨",
  "假日早上：吃完早餐回來後已經充滿人潮",
  "假日早上：一早就人聲鼎沸、人山人海"
],
"expect_sources": [
  {"67": "早上 8 點開門就到,淺草寺幾乎沒什麼人"},
  {"124": "早上約 8 點多抵達，平時大排長龍的雷門只有零星幾人拍照"},
  {"67": "8 點時表參道只有一家人形燒店有開,之後店家逐漸開門,人開始變多", "124": "離開時店鋪已陸續開門，人潮正要開始增加"},
  {"62": "早上趁大批觀光客還沒湧入時拍照,畫面很乾淨"},
  {"62": "吃完早餐回來後已經充滿人潮"},
  {"135": "一早就人聲鼎沸、人山人海"}
]
```

判斷說明：

- 沒有「假日比平日多」這種結論：這四筆是不同旅客在不同月份的經驗，片段自己沒做這個比較。
- 「8 點過後人開始變多」的 `8` 要出現在引文裡，所以 67 的引文從「8 點時」開始截。
- 「店家陸續開門」不是人潮的狀態，不寫進那一條。

## 報告

最後寫 `ptt_v2/report.md`：

- 每個題型的題數，沒出滿 10 題的原因
- `coverage` 分布，用到的地點和題數
- 盲審的一致率（修正前）、不一致的地方和怎麼解決
- `plan` 讀法不同的題目和處理方式
- 校準改了哪些條、換掉哪些題
- 所有 `label_issues`
- 新發現的地點錯配

## 不要做

- 不要改 `questions/ptt/`、`data/ptt.db`，也不要改 `src/` 的程式碼。
- 不要用文章原文、網路或常識補資料，只用片段內容。
- 不要為了湊滿題數放寬任何一條規則。
