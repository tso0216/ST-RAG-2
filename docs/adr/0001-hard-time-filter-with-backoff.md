# 取消時間平滑，改成時段硬過濾加時間退讓

原本的設計把片段和問題的時間標籤轉成「月 × 平日／假日 × 小時」週期格網上的分布，兩邊都平滑，再用重疊度乘上語意分數排序。我們改成：抽取時由 LLM 把時間歸到固定的時段（早上、中午、下午、晚上、全天、不明），月份、平日／假日、時段三個維度在檢索時都硬過濾；找不到相符的片段時，先做時間退讓（時段和月份各往外擴一格），再做空間退讓，取回的證據都標記並揭露。

理由：

- 平滑是內部做法，站在使用者的角度不是有用的貢獻。使用者在意的是拿到對的時段的資訊，不是的話要講明，這件事用退讓加揭露就做得到。
- 資料規模化以後，同一個景點、同一個時段的片段夠多，硬過濾漏掉時間邊緣的片段可以接受。
- 兩邊都平滑時，時間完全相符的重疊度只有約 0.58，門檻難定，論文裡也難以解釋這個數字。

## Consequences

- 抽取 prompt 和 schema 要改，`main.db` 要重新抽取；題目檔的 `relevant_contents` 要重新對應。
- 「軟比對 vs 硬過濾」不再是論文的主張，原本的核心貢獻要重新決定。
- 時段比鐘點粗，「7 點沒人、10 點擠滿」都算早上。具體鐘點留在片段內容裡給生成器看，不拿來檢索。
